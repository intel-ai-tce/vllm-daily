  - `vllm/model_executor/layers/fused_moe/oracle/unquantized.py`
  - `vllm/model_executor/layers/fused_moe/utils.py`

### Summary

**What changed and why**  
Added an opt-in tensor-descriptor (TD) load/store path to the fused MoE kernel, gated by the VLLM_TRITON_USE_TD environment variable. This mirrors the attention TD path and aims to improve performance on XPU and Blackwell GPUs by using tile::gather4 instructions. The change also includes hardware capability checks, fallback for quantized weights, and a warning when the env var is set but ineffective.

**Technical impact**  
Introduces a new code path in the fused MoE kernel that uses tl.make_tensor_descriptor and gather/load instead of pointer arithmetic. The TD path is auto-enabled on XPU, opt-in on Blackwell CUDA, and disabled on older GPUs. Quantized weights always fall back to the pointer path. A static assert prevents simultaneous USE_TD and SWAP_AB. The kernel now requires a Triton scratch allocator on CUDA when using TD. Tests are parametrized over use_td with appropriate skips for unsupported hardware.

**Potential risks**  
The TD path may cause miscompilation when K is not a multiple of BLOCK_SIZE_K, which is handled by a fallback with a warning. The path is unvalidated for quantized weights and is disabled in that case. On Blackwell CUDA, the path is opt-in and may have slight performance regressions as shown in benchmarks. The change modifies the kernel signature and adds a new constant, which could affect kernel caching. The hardware gate uses has_device_capability(100) which may need updates for future architectures.

**Key insights**  
The TD path provides a ~6% throughput gain on XPU for realistic workloads (sharegpt) but shows small regressions on Blackwell CUDA, justifying the opt-in default. Accuracy is bit-identical to the pointer path on both B70 and B200. The implementation follows the single-flag design from RFC #42545 and includes comprehensive multi-platform validation. The fallback for non-block-aligned K addresses a known Triton compiler issue.

**Key insights**  
The root cause was asymmetry: only target model buffers were saved, while draft buffers were left uninitialized. The restore condition bug could silently corrupt state when wake order was KV-first. Removing the rebuild hook simplifies code and removes a hidden dependency on draft model internals.
