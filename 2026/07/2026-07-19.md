## 4. [[Bugfix] Fix logprobs token-string collision from SentencePiece space…](https://github.com/vllm-project/vllm/pull/48674)

  - `tests/tokenizers_/test_detokenize.py`
  - `vllm/tokenizers/detokenizer_utils.py`

### Summary

**What changed and why**  
Fixed a bug where SentencePiece's decode() strips leading spaces from tokens like '▁true', causing distinct tokens to collide when used as dictionary keys in top_logprobs. The fix adds a function to detect the space marker from the pre_tokenizer config and restore leading spaces after decode() by comparing with the raw vocab piece from convert_ids_to_tokens().

**Technical impact**  
Ensures that top_logprobs keys are unique even when SentencePiece tokens differ only by leading spaces, preventing logprob values from changing with the requested count. The change is backward-compatible for non-Metaspace tokenizers (e.g., BPE) and adds caching to avoid repeated config parsing.

**Potential risks**  
The fix relies on parsing the tokenizer's backend config JSON, which may fail for custom or exotic tokenizers; in such cases it falls back to no restoration. The caching mechanism uses a private attribute, which could conflict with other code. The restoration logic assumes the marker is a single character, which holds for SentencePiece but might not for custom pre_tokenizers.

**Key insights**  
The root cause is that SentencePiece's decode() inverts add_dummy_prefix, stripping leading spaces from the first token. Using convert_ids_to_tokens() to get the raw piece and then restoring stripped spaces is a minimal fix that preserves human-readable output while ensuring dictionary keys are collision-free.
