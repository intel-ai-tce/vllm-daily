### Summary

**What changed and why**  
This PR enables the single-copy (replicated) MLA layout for the default CPUOffloadingSpec backend by gating replicated_layout on a new per-spec hook _uses_shared_region() instead of the static SUPPORTS_REPLICATED_LAYOUT flag. The change allows the default backend to deduplicate replicated MLA KV across TP ranks when using the shared offload region (CUDA/ROCm), reducing host memory usage and D2H store traffic. The hook is the single source of truth for both sizing and worker allocation, preventing drift, and non-shared-region platforms (e.g., XPU) fail closed to the existing per-rank layout to avoid data corruption.

**Technical impact**  
The change modifies the replicated-layout gating logic in CPUOffloadingSpec and TieringOffloadingSpec, replacing the static capability flag with a dynamic platform-dependent hook. It updates create_worker to map all ranks to slot 0 under replicated layout, and adjusts sizing to use num_copies=1. Tests were added to cover the truth matrix, sizing, and rank assignment. This is a behavior change for CUDA-alike deployments using the default backend with replicated MLA: host cache capacity scales with TP and D2H store traffic drops to 1/TP. Non-CUDA-alike platforms and TieringOffloadingSpec behavior remain unchanged.

**Potential risks**  
The main risk is correctness on non-shared-region platforms (e.g., XPU) if the _uses_shared_region() hook is not accurate; the fail-closed design mitigates this. The change relies on the assumption that per-rank MLA KV is byte-identical in homogeneous TP without context parallelism; if that assumption is violated, deduplication could cause data corruption. The removal of SUPPORTS_REPLICATED_LAYOUT could break external subclasses that relied on it, though no in-tree specs used it. The new hook is not part of the public API and could be overridden incorrectly by subclasses.

**Key insights**  
The PR correctly identifies that the shared region is a prerequisite for safe deduplication and makes the platform gate load-bearing. The single source of truth hook prevents drift between sizing and allocation. The test coverage includes a data-loss guard for non-shared-region platforms, which is critical. The E2E result showing D2H store bytes dropping to exactly 1/TP confirms the dedup engages as expected. The change is well-scoped and aligns with the existing tiering spec behavior.
