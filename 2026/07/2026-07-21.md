## 1. [[Perf][Renderer] Offload derender CPU work to renderer thread pool](https://github.com/vllm-project/vllm/pull/49396)

- **Author:** [guan404ming](https://github.com/guan404ming)

- **[Changed Files](https://github.com/vllm-project/vllm/pull/49396/files) (1):**
  - `vllm/renderers/online_derenderer.py`

### Summary

**What changed and why**  
Offloaded CPU-bound derender work (detokenization, logprob resolution, parsing) from async handlers to the renderer's shared thread pool using make_async. This prevents blocking the event loop for all concurrent requests, improving responsiveness under load.

**Technical impact**  
The change introduces two new async wrappers (_derender_chat_async, _derender_completion_async) that run the synchronous logic on a thread pool executor. The public async API remains unchanged. Benchmark results show probe latency drops from hundreds of ms to ~12ms (p50) and throughput for heavy requests is unaffected.

**Potential risks**  
If the executor is not properly sized or shared, thread pool exhaustion could occur under extreme load. The change assumes the synchronous methods are thread-safe; any shared mutable state (e.g., tokenizer) must be safe for concurrent access. The diff is small and focused, so risk is low.

**Key insights**  
The fix uses a simple one-hop offload pattern (make_async with executor) to convert synchronous CPU-bound work into non-blocking async calls. The benchmark data clearly shows the improvement in event-loop responsiveness without degrading heavy-request latency. This is a targeted performance optimization with minimal code change.

  - `vllm/compilation/passes/pass_manager.py`
  - `vllm/config/vllm.py`

### Summary

**What changed and why**  
Removed the `check_aiter_fused_qk_rmsnorm()` probe and its associated cache, which imported `aiter` at config time and caused HIP initialization in the parent process, forcing multiprocessing to use `spawn` instead of `fork`. This broke tests relying on `fork` for in-process model registration. The probe was redundant because the fused kernel is always present in the pinned AITER version. Also removed the legacy fallback path in `_fused_mla_dual_rms_norm_impl` that tried both old and new import names, now directly importing the private `_fused_qk_rmsnorm`.

**Technical impact**  
Eliminates a config-time HIP context initialization on ROCm when AITER is enabled, preserving the `fork` multiprocessing method for flows that require it (e.g., out-of-tree model registration). The MLA dual RMSNorm fusion pass is now gated only on `rocm_aiter_ops.is_enabled()`, which does not trigger HIP init. The change simplifies the code by removing ~60 lines of dead or redundant logic.

**Potential risks**  
Low risk. The removed probe was redundant (always returned True on the pinned AITER version). The direct import of `_fused_qk_rmsnorm` assumes the private API is stable; if AITER changes the function name, the import will fail. However, the PR description notes the API is stable since PR #2958. The legacy fallback removal could break users on older AITER versions, but the pinned version is v0.1.16.post3 which includes the private name.

**Key insights**  
The root cause was a subtle side effect: importing `aiter` to check for a kernel's existence triggered HIP initialization, which forced `spawn` and broke `fork`-dependent tests. This highlights the importance of avoiding accelerator library imports at config time. The fix removes the unnecessary check entirely, relying on the fact that the kernel is always available in the supported AITER version.

## 6. [[Bugfix][Attention] Ignore empty MLA context chunks during merge](https://github.com/vllm-project/vllm/pull/49294)


### Base Information

- **PR Number:** #49294
- **Author:** [LucasWilkinson](https://github.com/LucasWilkinson)
- **Merged By:** [MatthewBonanni](https://github.com/MatthewBonanni)

  - `tests/evals/gsm8k/configs/GLM-5.2-NVFP4-TP2-PCP2-EP.yaml`
  - `tests/kernels/attention/test_merge_attn_states.py`
  - `vllm/model_executor/layers/attention/mla_attention.py`
  - `vllm/v1/attention/ops/triton_merge_attn_states.py`

### Summary

**What changed and why**  
Added a Triton kernel `mask_empty_context` that detects prefill rows with zero context length and sets their LSE to -inf and output to zero before merging attention states. This prevents undefined partial attention (NaN/Inf) from corrupting the merged result when a context chunk contains no keys for some queries. Also added a guard in the merge kernel to handle the case where both sides are empty (both LSE -inf) by outputting zero instead of NaN. Updated the MLA attention code to call the mask for chunks that have empty context rows, and added a test for the mask and a test for merging two empty sides. Additionally, pinned the max-num-batched-tokens to 32768 in two evaluation configs to match the validated token budget.

**Technical impact**  
Fixes a correctness bug in multi-head latent attention (MLA) with prefix caching and context parallelism where empty context chunks could produce NaN/Inf outputs that propagate through merge_attn_states, corrupting prefill results. The fix is efficient: it uses a single Triton kernel that resolves query-block ownership via warp-local reduction, avoiding per-token metadata. The merge kernel also now safely handles the fully-undefined corner case. Evaluation accuracy improved from 1/100 to 93/100 on GSM8K.

**Potential risks**  
The new kernel introduces additional GPU kernel launch overhead, but only for chunks that actually contain empty context rows (detected via a boolean flag). The warp-local reduction assumes at most 32 requests per warp chunk; if the number of requests exceeds this, the kernel may misidentify the request index. However, the code uses a while loop that processes 32 requests at a time, so it should handle arbitrary numbers. The mask is applied only when `has_empty_context[i]` is true, so there is no performance impact for chunks without empty rows. The changes are limited to the MLA attention path and do not affect other attention backends.

**Key insights**  
The root cause was that the backend returns a finite LSE for empty context chunks, even though the output is undefined. By explicitly marking empty rows with -inf LSE and zero output before merging, the fix ensures that merge_attn_states can remain generic and not need to reason about undefined partials. The Triton kernel design is clever: it uses a warp-local reduction to map query blocks to request indices without per-token metadata, and it only launches for chunks that have empty context rows. The fix also includes a safety guard in the merge kernel for the case where both sides are empty, which would otherwise produce NaN from 0/0 scaling.
