  - `vllm/models/deepseek_v41/nvidia/model.py`
  - `vllm/models/deepseek_v41/nvidia/model_state.py`

### Summary

**What changed and why**  
This PR enables automatic prefix caching (APC) together with encoder-side SWA bounded replay for DeepSeek-V4.1-Flash under prefill context parallelism (PCP). Previously PCP rejected APC; the change relaxes the NotImplementedError guard in nvidia/model.py to allow prefix caching when swa_bounded_replay is set, updates the attention.py warning condition, and modifies model_state.py to stage replay starts per local PCP segment, mask each rank's own cacheable slots, and all-gather them in rank-major order. Tests are updated to set prefill_context_parallel_size=1.

**Technical impact**  
Behavior changes in the PCP path: replay start buffers are sized for local PCP segments (2x max_num_reqs when PCP>1), slot mappings are chunked per PCP rank before padding, and a new collective (get_pcp_group().all_gather) synchronizes masked cacheable slots across ranks. This collective applies only to PCP batches with encoder replay enabled, and the non-PCP path is preserved. The PR reports large TTFT and throughput gains with prefix-cache hit ratios around 79-84% and no accuracy regression in GSM8K.

**Potential risks**  
The new all-gather collective requires all PCP ranks to participate even when a peer has no replay rows, so any rank divergence or mismatch in batch composition could deadlock or corrupt slot metadata. The change is confined to DeepSeek-V4.1 and a narrow supported scope (CUDA, MRV2, eager, synchronous scheduling, PP=DP=DCP=1), but human line-by-line review is still pending and validation is outside CI. Correctness of the rank-major gather ordering relative to KV publication is critical and not covered by the small test diff.

**Key insights**  
The implementation reuses the existing scheduler replay boundary and padding kernel rather than adding new machinery, keeping complexity low (5 files, +31/-16). The guard change makes prefix caching conditional on SWA bounded replay under PCP, which is a sensible coupling since decoder-side replay remains unsupported. The performance evidence is strong but the statistical accuracy claim is appropriately caveated as non-significant, and the main residual concern is the cross-rank collective's robustness under uneven replay workloads.

Adds _reject_add_while_paused in EngineCore, a new FinishReason.PAUSED/ERROR path with a RequestError payload, OutputProcessor handling that raises RetryableRequestError and aborts n>1 siblings, and Rust frontend mapping to 503/UNAVAILABLE. **Key insights**

**What changed and why**  
The PR adds an else branch in CMakeLists.txt so that FUSED_GDN_DECODE_ARCHS is populated for CUDA < 13.0 builds, targeting 8.0;8.6;8.9;9.0a. Previously this variable was only set inside the CUDA >= 13.0 block, so CUDA 12.x builds (including published cu129 images) omitted the fused_gdn_decode_post_conv_mtp kernel and GDN models fell back to the Triton spec-decode path.

**Technical impact**  
CUDA 12.x builds now compile the fused GDN MTP decode kernel for SM80-SM90, enabling the faster CUDA path instead of the Triton fallback. CUDA >= 13.0 behavior is unchanged since the new code is in an else branch. The change is a build-configuration fix affecting which kernels are compiled and shipped.

**Potential risks**  
Only SM80 was validated on CUDA 12.9; SM86/SM89/SM90 on CUDA 12.x were not built or tested, so compilation or runtime issues on those targets are unverified. The kernel relies on cp.async and BF16 math being available on these archs, which is asserted but not exhaustively proven across all CUDA 12.x toolchains. Any arch-detection edge cases in cuda_archs_loose_intersection could also affect which targets get built.

**Key insights**  
The fix is small and targeted, correcting a gating bug that silently disabled a performance feature on all CUDA 12.x builds. Validation shows 102 tests passing with the patch versus 29 skips and 2 failures without it, plus a measured 0.48-0.76x kernel time versus Triton. The main gap is lack of testing on SM86/SM89/SM90 under CUDA 12.x.
