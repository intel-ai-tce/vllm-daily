  - `vllm/v1/worker/gpu/spec_decode/dspark/utils.py`

### Summary

**What changed and why**  
This PR fixes a bug in DSpark speculative decoding where the draft model's attention backend was set to None when the speculative config did not specify a backend, causing the draft to re-run backend auto-selection and potentially pick a different attention class than the target. The fix makes the draft inherit the target's attention backend when the speculative config names none, while an explicit backend in the speculative config still takes precedence.

**Technical impact**  
The change modifies the draft model configuration to use the target's attention backend as a fallback, preventing mismatched attention implementations that could lead to incorrect cache dtype and shape assumptions. This resolves a runtime error during forward pass when using DeepSeek V4 with a specific attention backend and DSpark, enabling the engine to initialize and serve correctly.

**Potential risks**  
The fix assumes that the target's attention backend is compatible with the draft model. If the draft model has different requirements, inheriting the target's backend might cause issues, but this is unlikely given the draft is derived from the target. The change is minimal and only affects the fallback path when no explicit backend is specified, so explicit user overrides remain unaffected.

**Key insights**  
The bug was caused by treating None as 'auto-select' rather than 'inherit from target', leading to silent divergence in attention backend selection. The fix is a one-line logical change with a clear comment, and it was verified with tests and model evaluations showing no regression in accuracy or performance.

This is a substantial change that touches many parts of the codebase, indicating a broad impact on model execution paths.

### Summary

**What changed and why**  
This PR optimizes the MTP draft path in DeepSeek-V3.2/GLM-5.2 by fusing the trailing all-reduce into the final RMSNorm on the non-sequence-parallel path, and by adding a get_top_tokens method that performs greedy draft token selection via vocab-parallel local argmax, avoiding the full-vocab all-gather in compute_logits. The changes aim to reduce communication overhead and improve throughput, especially at higher concurrency.

**Technical impact**  
The fusion eliminates a separate all-reduce operation by combining it with the RMSNorm, reducing kernel launches and memory traffic. The local argmax approach avoids a large all-gather (e.g., 19 MB per step at concurrency 64), which can significantly improve throughput. The changes are gated by existing flags (use_local_argmax_reduction) and preserve the sequence-parallel path unchanged. Benchmarks show up to 13.6% throughput improvement at concurrency 64 with no measurable accuracy change.

**Potential risks**  
The fused all-reduce and local argmax may produce slightly different numerical results due to accumulation order and tie-breaking, but accuracy benchmarks show no significant difference. The local argmax path may not be compatible with all configurations or future changes to the proposer protocol. The c=64 benchmark is based on a single A/B pair, so results may be noisy; cross-node variability is high. The get_top_tokens method assumes a specific protocol and may break if the proposer's interface changes.

**Key insights**  
The optimizations target communication bottlenecks in speculative decoding, which are more pronounced at higher concurrency. The fusion aligns with existing patterns in the main model, and the local argmax leverages the proposer's existing probe. The PR carefully separates changes that have already landed on main, avoiding duplication. The performance gains are attributed to reduced communication, not speculation luck, as acceptance length is slightly lower in the faster arm.
