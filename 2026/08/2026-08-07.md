### Summary

**What changed and why**  
This PR fixes a TOCTOU race in the shm_broadcast MessageQueue where the remote XPUB socket's port was probed with get_open_port() and then bound later, allowing another process to claim the port in between. The fix binds to tcp://<connect_ip>:0 to let the kernel assign a free port atomically, then recovers the actual port via zmq.LAST_ENDPOINT. The advertised address is rebuilt from the original connect_ip to avoid endpoint normalization drift (e.g., IPv6 formatting). A regression test was added to verify concurrent writers produce unique, connectable addresses.

**Technical impact**  
The change eliminates the race condition by using kernel-assigned port 0, which is atomic and avoids the probe-then-bind window. It also ensures the advertised address remains consistent with the configured connect_ip, preventing handle string changes that could break remote readers. The new test exercises concurrent writer creation and verifies address uniqueness and message delivery, improving test coverage for this distributed communication path.

**Potential risks**  
The fix relies on zmq.LAST_ENDPOINT, which returns a bytes object that must be decoded and parsed; if the endpoint format changes or is not as expected, port extraction could fail. Also, binding to port 0 may have subtle differences in behavior across ZMQ versions or platforms, though it is a standard feature. The test uses a monkeypatched get_open_port to force collisions, but it only covers IPv4; IPv6 is mentioned in the PR description but not in the test. The change is minimal and localized, but any regression in port assignment could affect distributed communication reliability.

**Key insights**  
The PR correctly identifies that the race is triggered by the probe-then-bind pattern, which is exacerbated by deterministic port scanning when VLLM_PORT is set. Using port 0 is a clean, idiomatic solution that leverages the kernel's atomic port allocation. The careful handling of LAST_ENDPOINT to rebuild the address from connect_ip shows attention to edge cases like IPv6 normalization. The test design cleverly forces the race by monkeypatching get_open_port to return a fixed port, making the pre-fix code fail deterministically. The PR also acknowledges and supersedes a related stalled PR, preserving the original author's work, which is good collaborative practice.

The ROCm subclass forward method duplicates logic and could diverge from the main implementation. Performance gains are based on a single benchmark with dummy weights and may not generalize to all workloads.
