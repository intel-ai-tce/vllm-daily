  - `vllm/model_executor/models/deepseek_eagle3.py`

### Summary

**What changed and why**  
Removed a block in DeepseekV2Eagle3DecoderLayer.__init__ that manually rebuilt config.rope_parameters from config.rope_scaling before passing the config to DeepseekV2MLAAttention. The block caused crashes for plain-RoPE EAGLE3 drafts because it always set rope_type to 'deepseek_yarn' even when the draft had no rope_scaling, leading to a KeyError: 'factor' in get_rope. It also ignored apply_yarn_scaling and had a dead else branch. The fix relies on DeepseekV2MLAAttention's own normalization, which is idempotent and already handles the rope_type selection correctly.

**Technical impact**  
Fixes a bug where EAGLE3 draft models without rope_scaling (plain RoPE) failed to load, enabling spec decoding for such drafts. The change simplifies the code by removing redundant and harmful config manipulation, aligning the draft layer's behavior with the non-draft DeepseekV2DecoderLayer. No regression on the YaRN path is expected because DeepseekV2MLAAttention's normalization produces the same result for YaRN configs.

**Potential risks**  
The change relies on DeepseekV2MLAAttention's internal normalization being always invoked and correct. If that normalization is ever changed or skipped, the draft layer could break. Also, the removal of copy.copy(config) means the config object is shared across layers, but this is already the case for non-draft layers and is safe because the normalization is idempotent. There is a small risk that other code paths expect the config to be copied, but the diff shows no other usage of the copied config in the layer.

**Key insights**  
The bug was caused by a misunderstanding of Transformers v5's rope_scaling alias, which always returns a truthy dict, making the 'if rope_scaling' branch always execute. The fix correctly delegates rope normalization to DeepseekV2MLAAttention, which already handles both deepseek_yarn and deepseek_llama_scaling selection. The unit tests confirm the fix works for both YaRN and plain-RoPE configs, and the E2E test shows no regression in acceptance rate.

**Technical impact**

The helper assumes input_features and input_features_mask are either both tensors or both lists; mismatched types could cause errors. The change relies on the audio tower correctly handling the mask, which is already in place. The test requires downloading models and may be skipped if assets are unavailable, but it is a core model test. There is a slight risk of performance overhead from padding, but it is negligible for typical batch sizes.

**Key insights**  
The bug stems from a mismatch between the unpad-per-item design and the batched field config's behavior. The fix elegantly re-pads at the model level, preserving cache independence. The PR also addresses a gap where Gemma3n was broken but not covered by other PRs.

The new successful_keys field is optional and only used for promotion jobs; demotion jobs ignore it. The PR addresses a real inefficiency in the KV offload tiering system by allowing partial reuse of fetched data.
