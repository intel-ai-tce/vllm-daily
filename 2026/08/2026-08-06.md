### Summary

**What changed and why**  
This PR adds a ROCm-specific LatentMoERunner (ROCmLatentMoERunner) for Kimi-K3 that shards the routed up-projection in a column-parallel manner, mirroring the CUDA path's Tier 2 optimization. Previously, the ROCm path used a replicated up-projection where each TP rank computed the full projection redundantly. The change wires this runner into the FusedMoeFactory via runner_cls and includes comprehensive tests to verify correctness and sharding behavior.

**Technical impact**  
The change introduces a new class that overrides the forward and _fused_forward methods to conditionally use a sharded up-projection path. It computes only the local shard of the hidden states, accumulates into the shared output via addmm_ (beta-add epilogue), and relies on the final all-reduce to combine partials. This reduces redundant computation and improves throughput by 3-5% on MI355X as measured in E2E benchmarks. The change also adds a new test file with multi-GPU tests and unit tests for sharding logic.

**Potential risks**  
The sharding path is only enabled under specific conditions (tp_size > 1, hidden size divisible by tp_size, shared experts present, no sequence parallelism, scaling factor 1.0). If these conditions are not met, it falls back to the replicated path, which is safe but may not get the performance benefit. The implementation relies on the correctness of the all-reduce and the assumption that the shared output is not pre-reduced; if the fused output is already reduced, it falls back to the base path. There is a risk of numerical differences due to the change in computation order (sharded vs. full projection), but tests assert close matches with tolerances. The new tests use multi-GPU spawning and may be flaky in CI environments without proper GPU resources.

**Key insights**  
The PR demonstrates a performance optimization by avoiding redundant computation in tensor-parallel inference. The sharding strategy is carefully guarded by conditions to ensure correctness. The tests are thorough, including both arithmetic equivalence checks and behavior checks for when sharding should or should not be applied. The use of addmm_ to fold the shared partial into the GEMM epilogue is an efficient implementation detail. The PR also includes a fallback warning for unsupported configurations, which aids in debugging.
